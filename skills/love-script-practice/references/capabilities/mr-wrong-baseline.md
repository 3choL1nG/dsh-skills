# 底线筛选：排除 Mr.Wrong

> slug: mr-wrong-baseline ｜ 重要性: high ｜ 覆盖任务: task-06, task-07
> 一句话: 每条底线都要通过「不能忍受的问题 ≠ 希望的特点」这一检验，总数砍到 3 条（0.5³＝12.5% 量级），替换旧底线必须比旧的更难接受。

**0.5 理论（L436–L437 属已确认排版污染行，按红线不逐字引用，以下为概括）**：作者引台湾大学社会学教授孙中兴的「0.5 理论」——每一条底线相当于排除掉人群中约一半的人；身高不能低于多少、年龄范围、教育背景各乘 0.5 之后，适合的人只剩下 12.5%。0.5 是经验估计而非实测参数，原文未说明各条是否统计独立。**口径可能过时，不得作为前置事实断言**，本卡只把它当「加码条数」的量级提示。

## I — 方法骨架

解决的问题：择偶时的「找到对的人」是一个没有停止条件的搜索问题，所以永远觉得「差一点」；本卡把它换成有停止条件的排除问题。
输入：① 一张写满「在意点」的清单（用户的直觉原样，先不分类）；② 至少一段已发生的关系经历（用来暴露真实的敏感点）。
判据（核心）：逐条做「问题 / 特点」二选一——把条目写成「出现了 X」，若 X 只是「我喜欢的那种特点的缺席」（学历不够高、身高不够），它是理想；只有「X 出现就构成我不能忍受的问题」才进底线。
步骤：写全 → 划去「出现它我能接受」的 → 强迫只留三条 → 用 0.5^n 看容量 → 此后每出现一条新底线，与三条逐条比难受程度，只有「更难接受」才允许替换。
输出：三条底线卡 + 被划去项及理由 + 容量估算 + 替换判定记录（＋并列的行为底线三条勾选栏）。
边界：这是「预防风险」的逻辑，只负责把致命问题排除掉，不负责找到爱，也不保证剩下的人都可以；提不出或划不掉任何一条时，说明对自己还不了解，此时不硬凑三条。底线条目必须可观察，不写「三观不一致」。

## A1 — 案例

**案例 1（case_kind：作者亲历）**：作者自陈曾把「对方身高不能低于 1.7 米」当作找对象的底线，理由是受旧脚本影响、觉得男朋友一定要比自己高半个头。有一次她儿子不好好吃饭，她问「你以后喜欢的姑娘长得比你高怎么办呢」，儿子答「没问题啊，你看王祖蓝就找了个比他高很多的老婆」，她由此意识到**在儿子心目中，身高和爱情根本无关**（L431）。用途：一条「底线」可以在脑子里成立很多年而从未被检验过；它是「希望的特点」被误当成底线的标准样本。

**案例 2（case_kind：作者亲历）**：作者上学时有一位各方面优秀、也很关心她的学长，一直指导她做事，她却始终没感觉，当时不知原因。后来学长请她和男友吃饭，发现她男友不知道她爱吃什么、只管自己吃，便问她「你怎么找了这样一个不了解你的人」；可作者其实不喜欢有人帮她夹菜，那让她觉得「吃什么都不自由」。她由此发现自己交友的一条原则「我不喜欢别人控制我」，并意识到很难与「暖男型」男性长期交往——时间长了，关心就会变成控制（L442–L443，原书原句「关心和控制是没有严格界限的，你需要它的时候就是关心，不需要它的时候就是控制」）。用途：真底线往往不是想出来的，而是从一段具体经历里的不适感中辨认出来的，这正是 task-07 的更新机制。

**案例 3（case_kind：作者转述个案，原书未编号入案例库）**：一个男孩认为「女朋友一定要讲卫生、爱干净」是他的底线（作者称之为他的理想）；真遇到一个有洁癖的女友后，每次他不小心把食物污渍留在衣服上，女友就坐立不安、想方设法尽快去掉污渍，两人因卫生问题爆发多次争吵，这段关系就此结束。他随后发现**自己其实不能承受一个有洁癖的女朋友**，因为他自己并不那么注意卫生（L438）。原书未说明他之后是否把「不能忍受洁癖」正式写进底线清单。

## A2 — 触发场景与语言信号

**场景 1 · 完美主义式搜索**
- 中文信号：「我总觉得差一点」「我要找一个懂我的人」「他条件都不错，可我就是没感觉」「是不是我太挑了」。
- 英文信号：I'm looking for the one；I'll know it when I meet the right person；I don't want to settle。
- 处理入口：先用 f22 的链条破迷思（爱我≠懂我），再进三步法。

**场景 2 · 标准太多，挑不出来**
- 中文信号：「我列了十几条」「他符合八条还差三条」「我也不知道该砍哪一条」「筛到最后没人了」。
- 英文信号：my list is too long；he ticks 8 out of 10 boxes；I can't narrow it down。
- 处理入口：直接进三步法 + 0.5^n 容量核算。

**场景 3 · 该不该和这个人开始 / 要不要破例**
- 中文信号：「他有一条踩到我了，但他人特别好」「我是不是该给他一次机会」「为他破例降低底线可以吗」「第一印象就觉得不对，还要不要继续」。
- 英文信号：should I give him a chance；is this a dealbreaker；can I make an exception this once。
- 处理入口：先做「问题 vs 特点」检验，再走替换判定；破例＝不替换，必须写下放弃加码。

**场景 4 · 底线本身在变，新旧版本冲突**
- 中文信号：「我以前说过绝不找离异的，现在动摇了」「每谈一次我的标准就变一次」「我到底该信哪个版本的自己」。
- 英文信号：my standards keep changing；I said I'd never date someone divorced；which version of me should I trust。
- 处理入口：替换判定记录（只有更难接受才准替换），并把「自以为不能接受」降级。

**场景 5 · 被家人朋友的意见搅动**
- 中文信号：「我妈说他配不上我」「我朋友说他配不上我，另一个说他是真心的」「大家都劝我再看看」。
- 英文信号：my parents don't approve；my friends think I can do better；everyone tells me to keep looking。
- 处理入口：把第三方态度单独归档（它不是关于对方的可观察事实），只用它来触发一次自我核对；若症状其实是「用延迟与拒绝来测试对方」（对应反例 x16 与原则 p33），转 entry-into-love。

**与相邻能力卡的区分**
- 纠结的是「核心价值观是否一致」「要不要孩子」「这是底线题还是差异题」→ 用 three-view-triage；本卡只交付三条底线卡这一件产物。
- 对方已出现贬低、限制社交、亏欠感（消耗捆绑四标准命中两条以上）→ 先做 relationship-health-scan 的红线扫描，本卡不做安全评估。
- 出现动手、威胁、经济控制、以沉默惩罚 → **立即**转 safety-exit，停止底线清单流程。
- 纠结的是「要不要结婚/要不要辞职/要不要异地」这类契约级决定 → 转 marriage-decision。
- 症状是「我按老规矩付出却不被珍惜」「我的标准自相矛盾」→ 先做 love-script-audit 的脚本与双标自查。
- 问题是「怎么遇到人、怎么推进关系」→ 转 entry-into-love。

## E — 可执行步骤

**必需输入**（缺什么就必须先问）：
1. 用户写下的「在意点」清单的**完整条目**（不是「我要求不高」这类概括）；
2. 每条在意点的**具体触发情境**（上一次因为这一点不舒服，实际发生了什么）；
3. 至少一段已发生的关系经历及其敏感点（task-07 的原料）；
4. 涉及对方行为的关键事实（说了多久、有没有以关系为条件、有没有商量余地）——缺此不得把一句意向判成控制型底线。

**交付物与完成标准**：
1. **三条底线卡**（恰为 3 条）：每条 =「出现了 X（关于对方的可观察行为）」+「我打算怎么做」。
   完成标准：**逐条通过「问题 vs 特点」二选一检验**——把条目写成「出现了 X」，若 X 只是「我喜欢的那种特点的缺席」（学历不够高、身高不够、不是江浙人），判为**特点**，退回重写；只有「X 出现就构成我不能忍受的问题」才通过。三条中任一条不通过，本次交付不算完成。
2. **被划去项及理由**（≥1 条）：每条含「出现它我能接受」的具体事实理由；只写「那就算了吧」不算划去。
3. **容量估算**：保留条数 → 0.5^n 百分比；必须附「0.5 为经验估计，非实测；各条不独立时该公式会高估排除力度；口径可能过时，不得作为前置事实断言」。
4. **替换判定记录**（**无「待定」项**）：旧底线 → 新敏感点 → 难受程度比较 → 判定（替换／降级为「自以为不能接受」／不允许加入）。
5. **（并列）行为底线三条勾选栏**：与朋友经济来往／身体亲密接触是否都是自己想要的／是否与不熟的人去非公共空间。

**步骤**：
1. **破迷思**：把「他符合 8/11 条」「我到底该不该继续」判定为无停止条件的度量，改写为「我有哪些不能忍受的问题」。
   *判据*：用户能说出「我要的不是『他值不值得』，而是『我不能忍什么』」。
   *判停*：用户只要「他行不行」的判决、拒绝改写 → 停手，说明本卡不给判决，转 marriage-decision。
2. **写全**：逐条改写为「出现了 X」并补触发情境，一直写到自己想不出为止。
   *判据*：第三方态度（父母/朋友的意见）单独归档，不进清单——X 必须是关于**对方**的可观察事实。
   *判停*：情境中出现限制社交、查手机、经济控制、言语贬低、动手 → **立即**转 safety-exit。
3. **划去可接受的**：对每条问「如果一定会有其中一条，我选忍受哪一条」，并追问「有什么让我难以接受／不能选他」（坏处的信息量高于好处）。
   *判据*：划去必须附「我能忍」的理由。
   *判停*：一条也划不掉，或全部都想划掉 → 说明对自己还不了解，停手转 love-script-audit 的自我了解路径，**不硬凑三条**。
4. **强留三条**：强迫只留三个在意的点。
   *判停*：三条里出现「三观不一致」这类不可观察项 → 退回改写条目，或转 three-view-triage。
5. **容量核算**：算 0.5^n（3 条 = 12.5% 量级）；若保留条数远多于 3，如实标出外推值并注明「本次算术外推，非原书数字」。
   *判据*：用户能复述「再加一条标准＝再砍掉一半可交往人群」。
6. **替换判定**：新底线与现有三条逐条比难受程度，只有更难接受才替换；不能替换就放弃加码（不得往上码）。
   *判据*：替换记录里每条都有明确判定，无待定项。
7. **勾行为底线三条**，与择偶三条分开交付；任一格已破例 → 先转 relationship-health-scan 处理行动风险。
8. **收尾声明**：本卡只完成预防风险的逻辑；排除 Mr.Wrong 之后要找的是「让你快乐或受益的人」，后半段不在本卡。

## B — 边界与反场景

**不适用场景**
1. 正在发生的人身暴力、威胁、限制人身自由或经济控制：一切关系分析与筛选流程停止，直接走安全与支持路径。
2. 用户要的是「帮我判断他行不行 / 该不该分手」的裁决：本卡只产出底线卡与替换记录，不代做去留结论。
3. 已有明确底线，真正的纠结点是婚姻、辞职、异地等契约级安排：转 marriage-decision，本卡不覆盖让渡权利的评估。
4. 争议围绕星座、八字、塔罗等命理式匹配，或要求「如何在标准上更占优势」的博弈技巧。
5. 用户只想要「证明我要求不高、是他不行」：此时任何改写都会被读成指责，先做合作确认；用户拒绝改写条目即停手（对应反例 x15 的抗拒面）。

**作者警告的失败模式**
- **x14 Mr.Right 迷思与「猜猜猜」游戏**：把「爱我」等同于「懂我」，衍生出「我不说你也该懂」的考核，用猜中率评价伴侣，白白错过大量本可发展的关系。纠偏方向即本卡：不存在 Mr.Right，要做的是排除 Mr.Wrong，需求要直接说。
- **x15 把理想当作底线**：把「我希望的特点」逐条写进底线清单，越写越多，并随意把新底线加进来。后果：每加一条就排除人群中一半，适婚人群被自己清空。纠偏方向＝三步法 + 容量核算 + 更难接受才可替换。
- **x03 把「秒回」当作爱的标准**：用极低成本、极易验证的行为指标直接充当爱意判据并据此排除对象；它还会与「希望他有上进心」互相冲突（认真工作的人在工作时间无法秒回）。
- **x16 故作矜持：考验与测试对方**（对应原则 p33，主归属 entry-into-love）：用延迟、拒绝、制造稀缺来测试诚意，会同时削弱「是」与「不」的力量；与本卡的关联是它和 x14 的「猜猜猜」是同一种「让对方猜」的模式。

**作者的盲点与时代局限**
1. **判据只能校验形式，不能校验内容**。作者自己在 L431 就把「身高 1.7 米」当底线用了多年，说明「不能忍受」是可错且会变的主观判断（L444 亦自承有「自以为不能接受」）。据 BOOK_OVERVIEW §3.4「最强反驳一」，本书框架有不可证伪的风险：任何失败都能被解释为「底线没找对」。因此本卡**无法区分**「清单是对的、只是这个人不合适」与「清单本身错了」两种情况；E 段完成标准只绑形式（是问题不是特点、恰三条、可观察、无待定项），不写「你的底线是对的」。
2. **0.5 理论的量级与人群口径**。0.5 是借来的经验估计而非实测参数，原文未说明各条底线是否统计独立；收入与学历等条件正相关时，0.5^n 会高估排除力度，12.5% 只是作者举例的量级。据 BOOK_OVERVIEW §3.1，本书样本偏向中国城市中产与高知群体、关键统计为 2015–2018 年口径——本卡的容量数字**不得当作人群测算或前置事实**，只用于说服自己减少加码条数。
3. **把择偶困难再次个人化的风险**。据 BOOK_OVERVIEW §3.2，作者反复把关系改善的责任放回个体身上。若本卡被用来解释「你找不到人，是因为你的底线清单没写好」，就会掩盖梯度理论、性别脚本变迁不同步等结构错配（那属于 entry-into-love 与 love-script-audit 的辖区）。本卡不评价用户「挑」或「不挑」。

**相关能力**
- composes-with: `love-script-audit`（先辨脚本与双标，再来筛底线）
- composes-with: `three-view-triage`（核心三观类条目由它分流，本卡不承载四题型流程）
- composes-with: `relationship-health-scan`（红线命中与行为底线破例时先走它）
- contrasts-with: `safety-exit`（安全分支命中即停止筛选流程，契约相反）
- contrasts-with: `marriage-decision`（契约级决策与本卡的筛选契约不同）
