# 爱情脚本自查与双标检测

> slug: love-script-audit ｜ 重要性: high ｜ 覆盖任务: task-01
> 一句话: 当用户说「总是遇不到合适的人」时，交付「我的爱情脚本」条目表 + 内部矛盾清单 + 取舍决定（无待定项）三样产物；每条双标按「要对方承担 X ⇒ 我是否承担对应 Y」判，Y 为空或与 X 互斥即命中。

## I — 方法骨架

解决什么问题：用户把「遇不到合适的人」归因为自身条件、运气或对方人品，于是问题无法推进；实际上卡住他的是**一套没被说出口、且内部互相矛盾的择偶脚本**。

输入：一段择偶/相处困境的自述 + **逐条化的期待清单** + **自己已承担的责任事实**（后两项缺失时必须先问）。

判据与步骤：
1. **归因迁移**——先把「我性格有问题 / 他人品差 / 原生家庭」三类归因挂起，改判为「我的脚本可能混杂」；这一步只改判问题的位置，不减责任。
2. **脚本定位**——用四问（我的脚本是什么 / 偏传统还是现代 / 我认不认可它的价值观 / 这个角色我演不演得好）＋旧脚本五要素、新脚本三要素逐条打勾，再判婚姻模式是缘分（减法）还是爱情（加法）。
3. **双标检测（核心）**——把每条期待写成条件句两半：「我要对方做 X」⇒「我承担对应的 Y」。Y 为空、或 Y 与 X 互斥（如要求秒回又要求上进心），即命中。
4. **取舍**——每条命中项二选一：保留 X 则接受 Y 的具体成本并给出第一个动作；或改期待并写下替换表述。不允许"再等等看"。

输出：条目表（条目 / 新旧脚本归属 / 我承担的 Y）＋ 内部矛盾清单（每条能指回一句用户原话）＋ 取舍决定。

**冲突归因：是角色期待错位，不是性格不合**（脚本诊断镜头，本单元的一等判据）
- 解决的问题：把一次两性冲突读成"性格不合 / 三观不一致 / 对方是渣"，于是找不到可改的着力点。
- 做法：①先判冲突性质——旧脚本下主要是"个体特质 vs 角色要求"的冲突（做不好女红、演不好严父），新脚本下才表现为"性格不合、三观不一致"；②分别检查两性脚本的变迁速度——男性脚本几乎没变、改变动力不足（"男主外、女主内"在现代社会让男性更受益），女性面对"双重负担"（既要人格独立、又被要求吻合传统家庭角色）；③识别"双重负担"是否存在于本段自述中；④把对"渣男渣女"的道德抱怨转为对个体不同情况的了解（L156）。
- 输出：冲突归因从**人品判断**改写为**角色期待错位判断**；该结论直接喂给第 3 步——错位常常正是"要对方承担 X、自己却不承担 Y"的另一种说法。
- 边界：原文同时要求"女性不要内化歧视"与"男性步子大一点"（L175），作者原意是两性都要反思、**男性尤其需要改变**；因此本判据**不产出"双方责任对等"的结论**，也不等于女性单方面让步。它只做归因，不处理"这一场冲突怎么谈"（那转 `conflict-protocol`）。

边界：本卡做的是**自洽性校验**，不是道德评分——原文明确"趋利避害的倾向本身无可厚非"（L164）。它也不承诺问题解决（L173：道理只能解决一部分问题）。命中安全/控制特征、或矛盾实为婚姻制度问题，一律转出。

## A1 — 案例

**案例：小A与「妇女节快乐」的分手** ｜ `case_kind`: **作者转述个案**（作者的朋友，非作者亲历）

作者的朋友小A（28 岁）反复感叹"谈恋爱太难了""总是遇不到合适的""遇到的都是奇葩男"（L88）。情人节男友没有任何表示，三八妇女节男友祝她"妇女节快乐"，她认为"妇女"是贬义词，一怒之下分手（L90）。第二年亲戚介绍一位同在上海工作的青年，她嫌对方穿旧夹克、拎坚果、去嘈杂餐厅、询问收入，当场判定是"奇葩"，拒绝继续相处（L91）。

作者没有安慰，而是一连串追问：他关心收入是功利，还是这次相亲就是奔着结婚去的？他穿旧夹克是不当回事，还是本来就不注意外表？（L97）小A被问住，最后自己说："我从来没有关心过他们是怎么想的，我只是觉得所谓的缘分就是找到一个'懂我'的人，而所谓'懂我'其实就是符合我的爱情模板。"（L104）

作者用它说明：独立女性以为自己走出了旧脚本，其实仍在按一套没被说出口的「爱情模板」挑人。**原书未说明后续结果**（是否继续相处、关系结局均未交代）。

## A2 — 触发场景与语言信号

**场景 1 · 反复「遇不到合适的人」**
- 中文：「总是遇不到合适的」「遇到的都是奇葩男」「好男人都结婚了」「我是不是命里没这个缘分」
- 英文："I keep meeting the wrong people." / "There are no good ones left." / "Maybe I'm just unlucky in love."

**场景 2 · 被说"太挑"**
- 中文：「身边人都说我太挑了」「我要求真的高吗」「条件都不差，可我就是没感觉」
- 英文："Am I being too picky?" / "Everyone says my standards are unrealistic." / "He's great on paper, but I feel nothing."

**场景 3 · 条件都好但"没感觉"**
- 中文：「聊不到一块去」「没有眼缘」「他很好，但不是我要的那种感觉」
- 英文："We just don't click." / "I can't explain it, the spark isn't there."

**场景 4 · 新旧标准同时挂在嘴上**
- 中文：「我自己能挣钱，但他不能比我差」「他要懂我，还要有事业心」「婚后当然要平等，家务嘛……」
- 英文："I want an equal partner, but he should still be the provider." / "He has to understand me without me explaining."

**与相邻能力卡的区分**：
- 自述里出现**限制社交、贬低、亏欠感、暴力**任何一条 → 用 `relationship-health-scan`（命中两条即警觉），不要继续做脚本分析；若已涉安全 → `safety-exit`。
- 问题实为**「要不要结婚 / 要不要孩子」** → 用 `marriage-decision`（十问清单）。
- 卡点是**某一次具体冲突怎么谈** → 用 `conflict-protocol`；卡点是**当前这段关系还要不要** → 用 `crisis-navigation`。
- 用户要的是**筛掉具体某个人的底线**（"他这样能要吗"） → 用 `mr-wrong-baseline`；本卡不替代底线筛选。
- 用户明确说"我就想让他改"且拒绝讨论自己的期待 → 用 `difference-value-judgment`（把"他怎么可以这样"换成"他为什么这样"）。

## E — 可执行步骤

**必需输入（缺一个就先问，不要硬走）**
1. 一段困境自述（是否已有"总是遇不到"类表述）；
2. **逐条化的期待清单**——不能只有"有感觉""聊得来"这类词，必须逼出可列举项（收入、学历、家务、话语权、情绪价值、能否聊天）；
3. **自己当前的承担事实**——家务现状、职业与生育打算、是否接受与父母同住。
（可选：对方的答案。没有也能走，但结论须标注"单方口径，未与对方核对"。）

**交付物与完成标准**
- 「我的爱情脚本」条目表：每条期待 ≤1 行，三栏齐全（条目 / 新旧脚本归属 / 我承担的 Y）；**不允许**把多条合并成"我比较传统"。
- 内部矛盾清单：条目数 ≥1，且**每条都能指回一句用户原话**为证。
- 取舍决定：每条双标候选都有明确归属（保留 X + Y + 第一个动作，或改期待 + 替换表述）；**"待定"项数 = 0**。

**步骤**
1. **归因迁移**。把「我性格有问题 / 他人品差 / 原生家庭」三类归因先挂起，改写为「我可能在使用一套没被说出口的模板」。判据：能用一句话说出"我三次都在用同一套筛选器"。
   - 判停：用户拒绝承认存在任何自有标准、只要"帮我判断他行不行" → 停手，转 `mr-wrong-baseline`，或先做反鸡汤追问（"这个结论背后的机制是什么、在什么条件下成立"）。
2. **脚本定位**。答四问；旧脚本五要素（偶然性·缘分 / 外在性·一定要结婚 / 长久性·天长地久 / 男主外女主内 / 男尊女卑）与爱情新脚本三要素（个体努力·经营 / 选择的意义与自负后果 / 关系中的平等与发展）逐条标"认 / 不认"；再判婚姻模式是缘分（减法）还是爱情（加法），并检查是否落入混合型"命中注定我爱你"（既要激情与自我感受，又要缘分与天长地久）。
   - 判据：四问里有 ≥1 问答不出（最常见是"我认不认可它的价值观"）→ 标记"脚本未成形"，此项直接进矛盾清单。
   - 判停：四问全部答不出且用户要求"直接告诉我要不要继续" → 转 `three-view-triage` / `mr-wrong-baseline`（先分清底线与理想）。
3. **双标检测**。逐条把期待写成「要对方做 X ⇒ 我承担对应的 Y」。
   - 判据（二值，可查）：**Y 为空 → 命中**；**Y 与 X 互斥 → 命中**。原文给出的两条标准替换：要对方挣钱养家 ⇒ 自己承担家庭内分工；要对方有主见、经济独立 ⇒ 不能认为家务理所当然，至少承担一半家务（L169）。
   - 判停：任一 Y 落在"大是大非 / 安全 / 服从"层面 → 不做替换，转 `boundary-three-kinds` 或 `safety-exit`。
4. **取舍**。每条命中项二选一：(a) 保留 X，写出 Y 的具体成本 + 第一周的第一个动作；(b) 改期待，写下替换后的表述。
   - 判停：每条都选"都不肯" → 结束自查，如实告知"这是取舍未决，不是脚本不明"，把决定权交回用户；**不得代其选一条降低标准**。
5. **收尾声明**。标注"单方口径、未与对方核对"与"脚本不会一次定型，需在实践中反复澄清"。

**转出后不要回头做的事**：不要在脚本分析中途插入沟通话术（那是 `conflict-protocol` 的交付物），也不要在本卡内给"要不要分手"的结论。

## B — 边界与反场景

**不适用场景**
1. **安全/控制信号已出现**（限制社交、贬低并依赖其评价、亏欠感、暴力、PUA）：脚本分析会被误用为"再理解他一点"，此时应停止分析、先走安全路径。
2. **用户只要一个判决**（"你就告诉我他行不行 / 我该不该分"）：本卡产出的是自洽性结论，不是对第三方的判决，硬用会滑成替人做决定。
3. **对方不在场、且用户拒绝对自己的期待清单化**：输入不足，输出只会是"感觉 ≠ 判据"的空话，应退回只做归因迁移。
4. **核心矛盾是制度性/物质性约束**（房价、异地、赡养、生育成本、劳动法执行）：本卡是认知工具，给不出结构性方案；据 BOOK_OVERVIEW §3.1，作者本人也倾向"可自我操作的认知工具"。此时应明说"这不是脚本问题"，不要把它硬读成双标。
5. **纯情绪安抚时刻**：用户当下只需要被听见，此时做双标检测＝把安慰变成审讯。

**作者警告的失败模式**
- `x01` 把情感鸡汤与个人经验当成爱情规律（`task-01`）：本卡的入口就要挡——任何"XX 的男人不能要"式断言，先问其成立条件与样本。
- `x04` 「只要权利不要责任」的择偶双标（`task-01`）：本卡的直接反例；形态为"既要旧脚本对方挣钱养家/温婉顾家，又要新脚本自己的平等与自主，却不愿承担对应的一半责任"。
- `x02`（**本卡主要承载**，`task-23` 为交叉引用）：相信"家不是讲道理的地方"、用无理取闹消耗爱——本卡在"只行使否决权、不承担对应的沟通责任"这一层挡它；其冲突现场的具体处置属 `conflict-protocol`，本卡不展开。
- `x03`（**本卡主要承载**，`task-06` 为交叉引用）：把"秒回"当作爱的标准——本卡在**认知层**挡它（单一行为不能作为爱的判据；要求秒回与要求上进心互相冲突，正是 Y 与 X 互斥的典型命中）。它挂在 `task-06` 只说明该误用还会污染底线筛选，**底线筛选流程归 `mr-wrong-baseline`，本卡不让渡 x03 的主要承载**。
- 另注：`counter-examples.md` 文末有 6 条「提取器补充观察」，**那不是原书内容**，本卡未引用。

**作者的盲点与时代局限（本卡在此处会失效）**
- **框架不可证伪**（BOOK_OVERVIEW §3.4 最强反驳一）："问题在脚本，不在个人"可以用来解释任何失败，而书中个案都是事后叙述。→ 本卡必须绑定**取舍决定无待定项**这个外部可检验的出口，否则纯解释什么都能圆。
- **可能把结构问题再个人化**（§3.2）：作者在导言反对个人化归因，却又把关系改善责任主要落在个体（常是女性）身上。→ 当用户的困境主要来自家务劳动未定价、职场歧视、异地/房价等结构性约束时，本卡的"改期待"会变成要求弱势一方继续让步，此时应明说"这是结构问题，不该由你的脚本自洽来承担"。
- **旧/新脚本二分是 2010s 中国城市语境**（§3.1）：样本偏一二线城市高知群体，全书关键统计为 2015–2018 年口径；对农村、流动人口、低收入群体与同性关系覆盖极薄。→ 面向这些受众时，"男主外女主内 / 男尊女卑"的旧脚本假设可能根本不成立，条目表需按用户实际语境重建而非照搬五项。
- **"至少一半家务"是原文唯一量化阈值**（L169），无计算依据；不得把它推广成对收入比例、带娃时长等其他项的量化标准。

## 相关能力

- composes-with: `mr-wrong-baseline`（脚本条目表 → 底线筛选；先分清底线与理想，再谈修正期待）
- composes-with: `difference-value-judgment`（归因迁移之后，"他为什么这样"的追问是其操作面）
- composes-with: `boundary-three-kinds`（双标替换中任一 Y 涉及权利/责任/利益划分时，用其判定器收口）
- contrasts-with: `relationship-health-scan`（同样从"我的关系有问题"入手，但本卡查脚本、那张卡查风险；出现控制/贬低信号时优先后者）
- contrasts-with: `conflict-protocol`（本卡交付归因与取舍，不交付这一场冲突怎么谈）
